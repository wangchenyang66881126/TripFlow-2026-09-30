# 有限扩容准备：验收记录

本轮完成本地代码和部署包准备，未创建云端函数，不能作为公网 100 / 500 人容量承诺。

## 产品经理可核对

1. 本机打开 http://127.0.0.1:53607/ ，点击「开始演示」，应出现重庆两日、16 站和固定攻略。
2. 切换 Day 1 / Day 2，查看酒店、百度交互地图和导航入口。分享地址 http://127.0.0.1:53607/share/cqpreset01 可直接恢复行程。
3. [实际导出长图](export.png) 来自原导出器及真实百度地图，固定演示多人共用同一文件。
4. 访问过多时，接口拒绝继续排队，前端显示“当前访问较多，请稍后重试。”，既有每日预算提示不会被覆盖。

## 检验结果和边界

- 后端全套 116/116；最后日志过滤调整后，相关 19/19 复测通过。前端 23/23；原有测试全部保留；TypeScript + Vite 生产构建通过。
- 真实本机 HTTP：两个独立进程交替接收请求，所有预设接口结果与原业务生成的快照一致；进程重启后导出任务仍可查询，PNG 字节保持一致。
- 20 个模拟用户：200/200 HTTP 成功；100 个模拟用户：1000/1000 HTTP 成功，单请求 p95 约 791ms；500 个模拟用户：5000/5000 HTTP 成功，但 p95 约 7496ms，已明显变慢。详细指标见 [本机报告](local-load.json)。这些测试读取固定行程、酒店、照片元数据、导航、分享和长图；不包含完整浏览器的所有资源请求，也不向百度发实时地图压测，运行机器并非云端 1c2g。
- 慢请求饱和测试：人为阻塞处理阶段，500 请求同时进入，限额 32；32 个获准执行、468 个快速得到 503 / SERVICE_BUSY / Retry-After，放行后恢复成功。另验证地图名额耗尽时普通 API 和健康检查可用，取消 / 异常会归还名额。该测试明确使用模拟慢请求，不冒充真实地图或云端压力结果。
- 浏览器检查：1263px 桌面及 390px 手机宽度无横向溢出，真实百度地图库和画布加载，Day 2 可选中，输入保持只读。截图工具 captureScreenshot 超时；未获得桌面/移动端视觉截图，不声称截图验收完成。导出 PNG 已实际查看。
- [部署包审计](package-audit.json)：无 .env、无本机数据库、未发现本机已知密钥。ZIP 约 8.0 MiB，包括 Linux x86_64 CPython 3.12 依赖。云端运行时验证仍待发布。
